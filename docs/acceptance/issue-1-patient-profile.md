# 总需求 #1：患者端个人中心原型

范围：患者端 `/prototype/patient-home` 内存原型。个人中心位于独立页面 `/prototype/patient-home/profile`，资料编辑和设置详情沿用弹窗。个人中心不展示病历、检查报告、AI 会话或医疗附件；这些内容仍由各自的医疗服务模块承载。原型不调用业务 API，刷新后恢复默认资料。

| 验收项 | 公开测试边界 | 当前结果 |
| --- | --- | --- |
| 从侧栏患者卡片、顶部用户按钮及两处导航进入独立个人中心页面 | `patient-home-prototype.spec.ts`：独立路由、直接刷新、页面标题、无概览弹窗 | 通过；四处入口均进入 `/prototype/patient-home/profile`，支持直接访问和刷新 |
| 顶部导航顺序与侧栏一致，个人中心选中并支持工作区标签 | 同上：导航顺序、选中状态、切换和关闭标签 | 通过；科室信息位于医生列表之前，个人中心位于站内通知之后；关闭标签返回首页；800/1024/1280/1440px 无导航遮挡或横向溢出 |
| 资料概览展示头像、昵称和脱敏手机号 | 同上：默认资料与手机号脱敏 | 通过；手机号展示为 `138****8000` |

| 不产生业务 API 请求 | 同上：监听 `/api/` 请求 | 通过；个人中心专项测试未产生业务 API 请求 |

限制：头像、昵称、手机号和通知偏好只在当前原型工作区内存中保存，刷新重置。验证码使用任意 6 位数字模拟校验；修改密码只校验表单，不核验真实旧密码或修改真实密码。退出及修改密码均返回登录原型，正式 `/profile` 和真实账户会话不变。协议使用示例文本，不接入短信、图片存储或通知投递服务。
