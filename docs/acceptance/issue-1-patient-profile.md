# 总需求 #1：患者端个人中心原型

范围：患者端 `/prototype/patient-home` 内存原型。个人中心不展示病历、检查报告、AI 会话或医疗附件；这些内容仍由各自的医疗服务模块承载。原型不调用业务 API，刷新后恢复默认资料。

| 验收项 | 公开测试边界 | 当前结果 |
| --- | --- | --- |
| 从侧栏患者卡片和顶部用户按钮打开个人中心 | `patient-home-prototype.spec.ts`：入口、弹窗标题、资料概览 | 待实现 |
| 资料概览展示头像、昵称和脱敏手机号 | 同上：默认资料与手机号脱敏 | 待实现 |
| 修改头像、昵称、手机号并预览保存 | 同上：本地图片预览、表单校验、保存成功反馈 | 待实现 |
| 未保存修改关闭时确认放弃 | 同上：编辑弹窗关闭与确认 | 待实现 |
| 通知设置即时保存 | 同上：系统通知、预约提醒两个开关 | 待实现 |
| 修改密码 | 同上：三项输入、两次新密码一致、成功后返回登录原型 | 待实现 |
| 隐私协议、用户协议和关于系统详情 | 同上：详情弹窗内容和返回个人中心 | 待实现 |
| 退出登录确认 | 同上：确认后返回 `/prototype/auth` | 待实现 |
| 移动端个人中心可用且无横向溢出 | 同上：375px 视口、弹窗布局 | 待实现 |
| 不产生业务 API 请求 | 同上：监听 `/api/` 请求 | 待实现 |
