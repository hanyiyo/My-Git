# D7 医生站内通知与只读个人资料接入验收

对应 GitHub 任务：[#30 医生站内通知与只读个人资料接入](https://github.com/hanyiyo/My-Git/issues/30)。

## 验收案例与公开边界

| 案例 | 公开边界 | 观察结果 | 限制 |
| --- | --- | --- | --- |
| 医生查看本人通知、区分待处理与普通通知，并看到未读数和业务待办数 | `GET /notifications?after=...`、`GET /notifications/unread`、`GET /doctor/home`、`/doctor/notifications` | 正式页面按持久化收件记录展示；替诊邀请和申请提醒进入待处理；待办数沿用申请事实；普通通知独立展示 | 待处理事件类型由当前治理通知契约识别 |
| SSE 断线或重新进入页面后补齐通知，重复消息不重复显示 | `/notifications/stream`、通知游标查询和 10 秒轮询 | 页面使用 SSE 作为唤醒信号，游标查询负责事实补齐并按通知 ID 去重；SSE 不可用时自动轮询 | 当前轮询周期固定为 10 秒 |
| 打开通知只标记本人收件记录已读，阅读不替代替诊确认或审核 | `POST /notifications/{id}/read`、通知详情 | 打开详情后才调用已读接口；“前往处理”进入申请或接诊页面，未直接执行业务动作 | 失效申请的最终拒绝仍由治理接口返回 |
| 个人中心展示真实身份、认证、科室和脱敏联系方式，并提供真实退出 | `GET /profile`、`GET /doctor/catalog/profile`、`GET /doctor/home`、`POST /auth/logout`、`/doctor/profile` | 姓名、职称、科室、认证状态、账号和手机号来自真实接口；资料编辑/改密明确未开放；接诊中退出二次提示且不结束接诊 | 联系方式编辑、密码修改和短信验证不在本任务范围 |
| 手机宽度和键盘入口可用，数据失败可重试 | 正式通知/资料页面浏览器验收 | 375px 无横向溢出；加载失败保留错误提示和重试入口；页面不展示演示资料 | 既有全套浏览器回归仍受临床流程偶发时序失败影响 |

## 验证记录

- 后端：现有通知 HTTP 契约覆盖本人隔离、游标补齐、已读幂等和 SSE；D7 使用真实 MySQL/Redis 的 `BrowserAcceptanceTest` 定向执行 2 个 Playwright 用例并通过。
- 前端：`npm run build` 已通过 Vue 类型检查、生产构建和生产资产隔离检查。
- 完整浏览器门禁的既有失败为 `workflows.spec.ts:74` 等临床流程时序问题，与 D7 页面无关；D7 定向验收通过。

## 当前限制

本任务不新增通知删除/批量操作、资料编辑、改密、短信或医院新闻后台；通知内容和申请事实继续由既有业务模块写入。GitHub Issue #30 保持开放，等待统一验收关闭。
