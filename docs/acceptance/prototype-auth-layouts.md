# 登录注册左右布局原型

问题：现有 `/prototype/auth` 页面纵向堆叠较多。比较三种左右结构，帮助确定登录注册切换、角色区分和验证码区域的布局；用户已选定方案 A，主色调整为深蓝；正式接口接入另行实施。

分支：`prototype/auth-layouts`，基于包含原型的本地集成提交 `06bca76`。仅在该原型分支比较，不发布到集成分支，也不替换真实 `/login`。

运行：在该工作树执行 `npm run dev:auth-prototype`，打开 `http://127.0.0.1:5181/prototype/auth?variant=A`。

| 方案 | 布局与交互 |
| --- | --- |
| A 深蓝分栏 | 左侧品牌介绍与纵向角色选择，右侧分段登录/注册切换；验证码紧邻输入框 |
| B 角色引导 | 左侧表单与两张登录/注册入口，右侧编号角色说明；验证码图示在输入框左侧 |
| C 服务工作台 | 左侧精简角色导航，右侧账户工作区；验证码独立分区，注册字段在宽屏分两列 |

底部开发态切换条、左右方向键及 `?variant=A/B/C` 共用路由；切换保留当前角色、表单、勾选和演示登录状态。输入框及可编辑区域内方向键仍用于编辑。刷新保留方案，清空内存中的演示资料；移动端改为上下排列。

患者与医生保留公开模拟注册；管理员仅提供登录，账号只能由管理员在后台创建。从注册状态切到管理员时回到登录，保留患者和医生的表单验证、演示填充、密码显隐和退出流程。现有原型没有验证码控件，本轮按用户要求补充纯展示、可换图的模拟验证码，不增加提交校验，不接真实登录或注册请求。真实登录页继续使用后端生成和校验的验证码。

## 管理员仅由后台创建

按用户补充要求，A/B/C 共用的管理员入口不显示注册选项，并提示“管理员账号只能由管理员在后台创建。”。从患者或医生注册状态切入管理员时强制回到登录，切回患者或医生仍可注册。

测试：扩展三套方案桌面验收，检查管理员无注册入口、无注册提交按钮，角色切换回登录；扩展手机验收，检查管理员仅登录、患者仍可注册。真实后端原已通过 `IdentityHttpTest.csrfAndRoleEscalationAndCrossAccountAccessAreRejected` 拒绝公开管理员注册，并通过 `administratorCanProvisionAndDisableAccountsWithoutTrustingStaleJwtRoles` 验证管理员后台创建；本次不修改后端与真实登录页。

本轮完整验证：`pwsh -NoProfile -File scripts/verify.ps1` 退出 0；86 项后端、23 项浏览器测试，零失败/错误/跳过，Vue 类型与构建、文档和真实 MySQL/Redis 验收通过。管理员原型定向检查在三套方案均通过，已检查 A 的管理员登录截图（忽略的 `.runtime/auth-admin-only.png`）；完整日志为 `.runtime/auth-admin-only-verify.log`。
