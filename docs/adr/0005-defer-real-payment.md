# MVP 暂不引入真实支付

状态：部分替代，参见 [ADR-0011](0011-paid-booking-holds-mvp.md)。

当前规则：首版不真实收款，但包含模拟支付订单、临时占号、超时释放和支付结果校验。下文保留为早期无支付 MVP 的决策背景，不能再作为“不建支付订单”的实施依据。

MVP 的 Appointment 不依赖真实支付即可完成预约闭环。系统保留未来接入 Payment 的边界，但首版不接入支付渠道、退款、支付回调或因支付超时导致的自动关单；这样可以先验证预约和问诊价值，避免支付基础设施成为首条业务链路的前置条件。

## 后果

- 首版界面必须明确这是演示预约流程，不得暗示已完成真实收费。
- 后续接入支付时，需要重新定义 Appointment 与 Payment 的状态一致性和退款规则。
