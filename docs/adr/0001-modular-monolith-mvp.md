# 采用模块化单体作为 MVP 后端架构

状态：accepted

MVP 采用一个 Spring Boot 模块化单体作为后端，使用 REST API 对外提供能力，并以领域模块隔离账户、预约、问诊、AI 辅助和管理功能；前端采用一个按角色呈现界面的 Vue 应用。选择它是因为当前目标是先验证完整预约问诊闭环，微服务会提前引入部署、事务和联调成本，而模块边界仍可为未来拆分提供清晰 seam。

## 考虑过的选项

- **微服务**：暂不采用。当前业务量和团队规模不足以抵消分布式部署、调用失败和数据一致性成本。
- **三套独立前端**：暂不采用。患者、医生和管理员共享认证、预约和问诊概念，首版使用一个前端的角色化路由更容易保持一致。

## 后果

- 模块之间必须通过明确的应用服务和领域对象边界协作，不能因为“单体”而共享任意表或跨模块修改数据。
- 未来拆分服务时仍需重新处理分布式事务、鉴权和部署，因此模块化单体不是对微服务的承诺。
