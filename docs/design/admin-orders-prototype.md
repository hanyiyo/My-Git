# 管理员预约与订单原型

状态：已确认并实现。入口为 `/prototype/admin-orders?tab=appointments`，使用虚构演示数据，不连接真实管理员订单接口。

## 页面定位

页面采用“预约运营工作台”模型，将预约登记、支付订单、退款异常放在同一个工作区的三个标签中。预约表达医疗服务履约，支付表达金额事实，退款表达资金退回处理；三者不能合并成一个订单状态。

默认打开预约登记标签，展示今日运营记录，并按待处理状态和出诊时间优先排序。页面提供日历下拉日期、预约状态、线上/线下、科室和关键词筛选；日历支持今天、最近两天和全部日期，筛选项与当前标签写入 URL，刷新和返回可以保留上下文。

## 标签内容

- **预约登记**：预约编号、患者、医生/科室、服务方式、预约来源、出诊时间、预约状态、支付状态、接诊状态和金额快照。
- **支付订单**：支付编号、关联预约、患者/医生、支付状态、金额、创建时间和支付时间；待付款记录展示截止时间。
- **退款异常**：退款编号、关联预约、退款原因、退款状态、尝试次数、下次处理时间和最近错误。

页面上方展示今日预约总量、待付款、候诊/就诊中和退款异常四项摘要。退款异常标签只提供重试和人工备注，不允许修改金额、重复创建退款或把失败演示成成功。

## 抽屉与操作

预约详情抽屉展示“预约创建 → 支付 → 签到 → 候诊/接诊 → 完成/取消/过期”的业务时间线。已付款、已确认且处于签到窗口内的预约可以执行管理员代签到，结果明确记录为管理员代签并进入候诊队列；其他状态显示不可操作原因。

支付详情抽屉强调支付不等于签到或完成接诊。退款详情抽屉展示退款时间线、失败原因、重试次数和人工备注；重试进入“处理中”，人工处理进入“等待人工跟进”，原记录保留。

医疗正文和附件不在此页面展示，管理员仍需单独医疗访问审核权限。页面底部明确标识虚构演示数据，不调用 `/api/`。

## 首页联动与访问路径

- 首页“预约与订单”进入 `/prototype/admin-orders?tab=appointments`。
- 首页“退款 / 异常”和退款待办进入 `/prototype/admin-orders?tab=refunds`。
- 页面标签切换使用 `appointments`、`payments`、`refunds` 查询参数。

## 验收边界

- 三个标签可切换，预约筛选与 URL 状态同步。
- 预约详情时间线和管理员代签到可演示，代签到后状态变为候诊中。
- 退款失败可重试，人工备注必填后保存，状态不会伪造成退款成功。
- 桌面表格在窄屏改为可滚动内容区，侧栏可打开关闭，页面无横向溢出。
