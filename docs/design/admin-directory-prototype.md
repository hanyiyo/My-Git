# 管理员账户原型

关联总需求 #1，用户已完成设计确认。在现有 `/prototype/admin-home?module=管理员账户` 内实现，保持管理员运营壳层与已有表格、抽屉、弹窗样式；不恢复历史三角色统一账户目录，不改变患者和医生入口。

## 信息与列表

仅管理管理员，固定演示操作者为运营管理员（ADM-001）。14条虚构账户覆盖启用10条、停用4条和当前账户，按创建时间倒序、编号作为相同时间的稳定排序。三张卡片统计完整目录的总数、启用数、停用数，不受筛选和分页影响。

筛选仅姓名/登录账号/编号关键词和启用状态，默认全部；每页10条，筛选变化回第一页，数据变化自动校正页码。列表含姓名、账号、脱敏手机号、状态、医院时间到秒的创建时间、详情和操作。当前账户显式标记。详情补充完整编号、手机号、管理员身份和本页操作记录，支持复制编号/账号及失败时手动复制反馈。不虚构最近登录、在线人数、设备会话或持久登录锁定。

## 新增、编辑与敏感操作

新增姓名必填、最多120字，手机号匹配大陆手机号 `1[3-9]` 后接9位数字；账号去首尾空格、统一小写，3–190位、字母数字开头，允许字母数字及 `@._+-`，按归一化结果检查整个演示目录的唯一性。初始密码及确认密码必填且一致；沿用现有服务的至少12字符、UTF-8最多72字节规则。密码仅在表单内校验，提交或实际关闭后清空，不存入账户、通知、记录或浏览器存储。

身份固定管理员，新增默认启用；账号创建后只读。编辑仅改姓名与手机号，无实质变化不能提交。新增/编辑取消、关闭、Esc及遮罩点击在有未保存输入时确认放弃，继续编辑保留输入。

启用、停用、重置登录状态均在独立弹窗显示目标账户和影响，二次确认前不更新数据。提交时再次检查资格；禁止停用当前账户、禁止重置当前账户的登录状态，确保完整目录始终至少有一个启用管理员。保护不依赖筛选结果，按钮不可用时显示原因。重置其他账户只演示让现有登录失效、要求重新登录，不改变密码、启用状态或业务记录；不提供删除、角色变更、密码重置或锁定操作。

新增成功清除筛选、回第一页并打开新账户详情。资料编辑及启停保留筛选，列表和详情同步；账户变更后不符合筛选时仍保留详情并提示。操作记录含动作、操作者、医院时间及必要说明，不含密码，不接真实审计或医疗审核资格。

刷新保留已保存演示数据、筛选、当前有效页及记录并同步详情；浏览器重载或离开模块后恢复初始数据。本页的资料和会话操作不调用真实接口。

## 真实能力差距

现有 `POST /api/v1/admin/accounts` 允许已启用ADMIN创建ADMIN，公开注册不能创建ADMIN；`PATCH /admin/accounts/{id}/enabled` 直接改enabled，没有自停用和最后管理员保护。停用时认证检查会拒绝旧JWT与刷新，但未撤销旧刷新会话，重新启用后旧会话可能恢复。原型不能宣称这些保护已在服务端生效。

当前没有管理员账户目录、资料维护、针对目标账户全部会话撤销接口，也没有管理员姓名/手机号的持久化档案；创建接口传入这些字段并不会为ADMIN保存。真实资料/唯一性、权限、事务内最后管理员保护、并发写入和全会话撤销均须接入前补齐。真实密码校验下限按Java字符串长度、上限按UTF-8字节，本原型保持相同计数方式。

Redis登录尝试限流是[验证码与限流边界](../adr/0014-redis-login-image-captcha.md)，不等于持久登录锁定。医疗审核资格沿用独立规则，本页不恢复隐藏入口。普通账户目录不展示医疗内容，遵循[最小可见性](../adr/0004-minimum-necessary-medical-visibility.md)。更新既有账户治理术语以反映分页面管理，不新增ADR。
