# 登录图形验证码与 Redis

已确认变更 R1：首版引入 Redis。已确认变更 R2：患者、医生、管理员使用账号密码登录时增加图形验证码。验证码为本地实际生成与校验，不发送短信或邮件；原演示身份核验策略继续有效。

范围入口：[当前 MVP](current-mvp.md)；架构：[架构草案](architecture.md)；取舍：[ADR-0014](../adr/0014-redis-login-image-captcha.md)。本次只更新设计，不安装 Redis 或实现登录代码。

## 登录流程

1. 登录页获取随机 `challengeId` 和验证码图片。生成结果绑定当前浏览器挑战会话，答案不下发给前端。
2. 后端将答案校验值、挑战绑定和有效期存入 Redis。建议默认 4 位不易混淆的字母数字、有效期 2 分钟；这些参数属于待整体确认的实现默认值。
3. 用户提交账号、密码、`challengeId`、验证码。登录入口先检查限流，再原子读取并消费该浏览器的挑战状态；不支持重复验证成功后另拿通行凭证绕过本次账号密码请求。
4. 验证缺失、错误、过期、已使用或绑定不符则拒绝，不校验密码；绑定不符不应消费别人的挑战。合法绑定上的一次校验尝试无论对错都耗用验证码，失败后获取新码。
5. 图形验证码正确才检查密码、账户禁用状态和可用角色；全部通过后签发 access token 和 refresh 会话。

正常刷新验证码使当前挑战会话的旧码失效；并发刷新按服务端当前挑战版本判断，迟到的旧图片不得使旧码重新有效。图片响应禁止缓存，生成答案、密码和 token 不写日志。浏览器绑定避免仅拿到别人的 challengeId 就能复用或消耗其验证码，绑定本身不等于用户已登录。

账号或密码错误只显示统一凭据错误，不透露账户是否存在。图形验证码不是第二认证因素，不替代密码哈希、后端权限、CSRF 防护或真实手机号/邮箱验证。

## Redis 职责

| 状态 | 存放位置 | 失效后的行为 |
| --- | --- | --- |
| 图形验证码、当前挑战版本及绑定 | Redis，TTL 自动清理 | 重新获取验证码，不允许旧请求通过 |
| 验证码获取/登录尝试的限流窗口 | Redis | 服务故障时拒绝新的登录验证，提示稍后重试 |
| 账户、角色、禁用与刷新会话 | MySQL | 持久化，按现有鉴权策略撤销和校验 |
| 号源占用、患者半天限制、排队恢复次数、支付退款 | MySQL | 保持数据库事务和唯一约束，不从 Redis TTL 推断释放 |
| AI/退款/到期任务、通知、审计 | MySQL | 进程重启恢复，不依赖 Redis Pub/Sub 保证送达 |

限流分别覆盖挑战生成和登录尝试，建议同时考虑来源与账号，窗口和阈值配置化；不只依赖 IP 永久锁定共享网络用户，不因验证码正确就跳过密码失败限流。具体阈值在实现与测试时确定。

验证码答案校验值使用带服务器密钥的 HMAC 等方式保护，不保存可直接读取的答案。登录验证和挑战消费在 Redis 原子操作中完成，先到请求获得本次尝试，后到请求不能重复使用；Redis 操作异常时不签发登录令牌，不能自动回退固定验证码或“演示万能码”。

## 故障与部署

Redis 不可用时，验证码获取或新登录返回可识别的暂不可用响应，前端保留账号输入并提供重试，不暴露内部连接信息。已有登录是否有效仍由 token、MySQL 刷新会话和权限决定；Redis 故障不主动取消患者预约，也不阻塞医生已登录的正常业务。

Windows 开发演示和单台 Linux 都配置 Redis；建议 Linux 与应用同私有网络部署，Redis 不暴露公网，凭据由环境配置注入。Redis 可清空或重启丢失挑战，用户重新获取即可；它不作为医疗记录备份的一部分，不要求其持久化来保障号源或任务正确性。

## 实现后的验收场景

- 三端登录均必须提交验证码，直接调用登录入口也不能绕过。
- 正确验证码和密码可登录；正确验证码配错密码后原验证码不能再使用。
- 缺失、错误、过期、刷新前旧码、已消费及其他浏览器挑战被拒绝。
- 同一码并发提交最多一个请求通过验证码校验，登录业务不会重复签发同一结果。
- 连续获取验证码、反复错密码和错验证码触发配置化限流。
- Redis 停止时新登录不降级放行，重启后旧码失效；已有业务不依赖它释放号源。
- 图片和验证码接口响应不含答案，日志不含密码、验证码答案和令牌。

以上为待实现验收要求，当前文档检查通过不表示这些运行时行为已验证。
