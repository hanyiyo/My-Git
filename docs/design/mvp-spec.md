# 智能医疗问诊预约系统 MVP 规格

## Problem Statement

单医院患者需要在同一平台完成线上问诊预约、线下预约或现场挂号，并在预约前获得受控的 AI 导诊帮助。医生需要在明确的候诊顺序中接诊，查看患者主动共享的材料，完成图文问诊或登记面诊结果。管理员需要维护医生资质、科室、排班、号源、停诊替诊和受控内容审核。

当前系统还没有业务实现；本规格把已确认的 Q1–Q66 业务决策、Redis 图形验证码修订和架构草案转成可实现的首版范围。

## Solution

采用单医院、三端、一个 Vue 应用、一个 Spring Boot 模块化单体、MySQL、Redis 和私有附件目录。

- 线上预约与线下预约共用登记、临时占号、模拟支付、凭证、签到、候诊和取消能力。
- 现场挂号只使用当天线下门诊的剩余号源。
- 医生按固定上午/下午门诊接诊；提前预约优先于现场挂号，恢复排队为第三优先级。
- AI 提供普通业务咨询和经授权的文本预问诊；AI 不能诊断、开处方或替代医生。
- 三端登录均要求账号、密码和一次性图形验证码；Redis 保存验证码挑战和登录限流，MySQL 保存账户与刷新会话。
- 业务状态、号源正确性、后台任务和医疗记录以 MySQL 为事实来源；Redis 不负责预约锁、退款、候诊或任务持久化。

## User Stories

1. 作为患者，我想注册并使用账号、密码和图形验证码登录，以便安全进入个人服务。
2. 作为患者，我想刷新验证码，以便在看不清时重新获取；旧验证码立即失效。
3. 作为患者，我想在验证码错误、过期、复用或 Redis 不可用时看到明确失败状态，而不是被错误登录。
4. 作为患者，我想查看医院、科室、已认证医生和有效上午/下午排班。
5. 作为患者，我想使用普通业务咨询助手查询地址、流程和一般科室职责。
6. 作为患者，我想描述自己的症状并在外发前看到预问诊授权说明。
7. 作为患者，我想让 AI 根据真实科室、已认证医生和有效排班给出导诊建议，而不是生成不存在的资源。
8. 作为患者，我想拒绝 AI 外发授权后仍能自行选择医生和排班。
9. 作为患者，我想选择线上或线下服务、医生和上午/下午门诊。
10. 作为患者，我想在同一日期同一半天只能持有一条有效登记，避免重复占号。
11. 作为患者，我想提交登记后获得限时临时占号，并看到支付截止时间。
12. 作为患者，我想使用模拟支付完成确认预约，并获得金额快照和预约凭证。
13. 作为患者，我想在付款迟到、停诊、拒绝替诊或允许取消时看到退款记录。
14. 作为患者，我想在预约订单页面进入签到窗口后签到，不需要定位或人脸验证。
15. 作为患者，我想在签到后进入候诊队列，并看到自己的队列状态。
16. 作为患者，我想在医生叫号后进入线上图文诊室或线下面诊流程。
17. 作为患者，我想在接诊前补充症状文本和授权共享的附件。
18. 作为患者，我想在医生叫号后发送图文消息，并在医生结束接诊后查看只读结果。
19. 作为患者，我想在医生过号后申请恢复排队；系统只允许本订单成功恢复一次。
20. 作为患者，我想在门诊时段结束后看到“本次门诊时段已经结束，无法恢复排队”，且知道该场景不退款。
21. 作为现场患者，我想在门诊开始后、首次签到截止前使用剩余线下号源挂号。
22. 作为医生，我想提交资质材料并看到审核状态。
23. 作为已认证医生，我想查看自己有效排班和候诊队列。
24. 作为医生，我想叫号、开始接诊、标记过号或结束接诊。
25. 作为医生，我想查看当前预约患者主动共享的材料和 AI 文本摘要。
26. 作为医生，我想提交问诊结果或登记面诊结果；结果保存作者和版本。
27. 作为医生，我想追加更正说明而不是覆盖已结束的医疗结果。
28. 作为科主任，我想审核本部门停诊申请并选择替诊或直接停诊。
29. 作为替诊医生，我想确认或拒绝替诊，并填写拒绝原因。
30. 作为管理员，我想复核替诊资质、科室和时间冲突并调整排班。
31. 作为管理员，我想审核自己的科主任申请回避场景，并处理紧急停诊。
32. 作为患者，我想在替诊生效后选择接受新医生或取消；等待期间保留原名额。
33. 作为管理员，我想查看停诊影响清单并通知患者重新选择有效排班。
34. 作为管理员，我想维护医院地址、业务流程和科室说明，供普通咨询助手使用。
35. 作为管理员，我想管理账号、医生、科室、排班、预约和 AI 调用元数据。
36. 作为审核人员，我想在独立授权、填写理由并记录审计后查看医疗正文或附件。
37. 作为审核人员，我想限制问题内容展示但保留原医疗记录。
38. 作为患者、医生或管理员，我想收到预约、取消、停诊、替诊、退款、叫号和签到提醒。
39. 作为系统，我想在 SSE 断线时允许客户端查询并补齐消息，不把连接当作事实来源。
40. 作为系统，我想在 AI、退款、占号超时或替诊确认任务失败后有限重试并保持幂等。
41. 作为系统，我想在外部 AI 最终失败时显示“暂不可用”，不静默切换为模拟答案。
42. 作为系统，我想在患者修改文本后标记旧摘要过时，手动生成绑定新材料版本和授权的新结果。

## Implementation Decisions

### Modules and interfaces

- `identity` 拥有账户、角色、患者资料、医生资质、刷新会话，并提供图形验证码登录、RBAC 和资源归属检查。
- `catalog` 拥有医院信息、科室、医生科室归属、科主任任命、固定上午/下午排班、号源和停诊替诊申请。
- `booking` 拥有临时占号、预约登记、患者半天 guard、预约凭证和替诊选择。
- `billing` 拥有模拟支付、金额快照、退款及幂等重试。
- `reception` 拥有签到、三组候诊、叫号、过号恢复和接诊过程。
- `clinical` 拥有材料版本、消息、问诊结果、更正、健康档案、共享授权和附件元信息。
- `ai` 拥有普通咨询、预问诊授权、文本任务、结果版本和调用元数据。
- `governance` 拥有审核、受限展示、医疗内容访问理由和审计。
- `delivery` 拥有站内消息、事件待发送和 MySQL 持久任务。

模块通过后端应用接口协作；Controller、Vue 页面和测试都使用同一业务接口。模块不能直接修改其他模块的 Mapper。AI、支付、文件存储、时钟和 Redis 是 Adapter seam；真实 provider 不进入默认测试路径。

### Authentication and Redis

- 登录先验证 Redis 中绑定浏览器挑战的一次性图形验证码，再验证账号密码和账户状态。
- 验证码建议 4 位不易混淆字母数字、TTL 2 分钟；最终阈值配置化。
- 验证码刷新令旧码失效；成功或失败的合法尝试消费验证码；绑定不符不消费别人的挑战。
- Redis 负责验证码 TTL、挑战原子消费、获取/登录限流；Redis 故障不签发新令牌，也不使用万能码降级。
- MySQL 负责账户、角色、可撤销 refresh 会话和全部业务持久状态。

### Booking, queue, and encounter

- 出诊按线上或线下、日期、固定上午/下午发布；默认上午 08:00–12:00、下午 14:00–18:00。
- 提前预约在门诊开始时停止新增；现场挂号可用剩余线下号源直到首次签到截止。
- 首次签到窗口为开始前 30 分钟至结束前 15 分钟；过号恢复窗口为门诊开始至结束。
- 临时占号期限取提交后 10 分钟和签到截止的较早值；支付有效才确认预约。
- 同半天提前预约优先现场挂号，恢复排队为第三组；各组按有效入队序号。
- 医生标记过号后，患者最多成功恢复一次；恢复者不恢复原预约优先级，后来的正常签到仍在恢复组前。
- 预约、支付、退款、签到、候诊、接诊和医疗记录分别保存状态；医生结束服务后预约完成，诊室只读。

### AI and files

- 普通业务咨询只使用管理员维护的医院事实；个人症状或报告先本地转入预问诊授权，原文不得先发外部模型分类。
- 外部 AI 需部署显式启用并取得本次材料授权；默认 mock/local 明确标识。
- 首版只分析已授权文本；图片、PDF 仅保存供医生查看。
- 附件只允许 JPEG、PNG、PDF，每份不超过 10 MB，每次最多 5 份；验证实际格式和权限。
- AI 失败有限重试，最终显示不可用，不阻塞自行挂号或医生接诊。
- 文本变化使旧摘要过时；手动生成的新结果绑定材料版本、授权、provider 和模型/提示版本，旧结果保留。

### API and event contracts

- REST 应用接口是主要验收 seam；关键写操作返回业务状态、幂等结果和可显示错误，不返回数据库异常。
- SSE 推送消息、叫号和站内通知；数据库是事实来源，断线按游标查询补齐，SSE 不可用时轮询。
- 附件下载必须走后端鉴权，不暴露本地路径或公开静态目录。
- 站内通知写入 MySQL 后异步投递；失败重试不改变预约、支付或队列状态。

### Data and deployment

- 单医院、一个 Vue 应用、一个 Spring Boot 模块化单体、MySQL、Redis、私有附件目录。
- Windows 本机开发，单台 Linux 部署；患者页面兼容手机浏览器，不做小程序或原生 App。
- 账号、订单、医疗记录、任务和审计在 MySQL；Redis 只保存可重建的验证码和限流状态。
- 使用 Flyway 管理 schema；数据库和附件目录联合备份；只使用虚构演示数据。

## Testing Decisions

- 主要测试 seam 是 Spring Boot 应用接口：测试通过 HTTP 或应用入口验证数据库、Redis 和事件的外部行为。
- 使用 MySQL/Redis 测试环境验证并发占号、患者半天唯一约束、临时占号截止、支付幂等、退款幂等、恢复一次和停诊审批。
- 使用 fake clock 验证上午/下午签到、现场挂号、过号恢复和通知提醒边界。
- 使用 mock/local AI、支付、文件和时钟 Adapter 验证授权、失败、有限重试、版本过时和不静默 mock。
- 使用浏览器验收覆盖患者、医生、科主任和管理员的关键流程，不测试 Vue 内部组件实现。
- 验证 SSE 断线查询补齐、权限撤回、附件越权防护、管理员审核理由和审计日志。
- 图形验证码测试覆盖缺失、错、过期、刷新、复用、绑定不符、并发消费、限流和 Redis 故障。
- 每个 tracer-bullet ticket 应同时包含 schema、API、UI 和外部行为测试；实现完成后运行单测、集成测试、端到端关键路径和完整回归。

## Out of Scope

- 真实支付、退款通道、短信、邮件、真实实名或手机号/邮箱所有权核验。
- 语音输入、图片/OCR AI 分析、实时音视频和复杂知识库。
- 多医院、多院区、代家属、未成年人和真实医疗机构上线。
- 真实检查、影像、药房、收费系统及院内系统对接。
- 小程序、原生 App、复杂统计、评价、自动化运维监控。
- 用 Redis 替代 MySQL 业务一致性、预约锁、候诊事实或持久任务。

## Further Notes

- 架构和业务规则记录在 `docs/design/` 与 `docs/adr/`；实现时必须使用 `GLOSSARY.md` 的术语。
- 早期无支付/提交即确认决策已由后续 ADR 部分替代；不得按旧段落实现。
- AI 结果永远是 AI-assisted result，医生保留最终判断；患者材料和外发授权必须可审计。
- 规格发布后，下一步运行 `/to-tickets`，把范围拆成有依赖边的纵向 tracer-bullet tickets。
