# 管理员药品与库存工作台

状态：设计已确认，进入正式管理员页面实现。

## 页面定位

正式管理员路由 `/admin/pharmacy` 负责维护 `Medicine（药品）` 基础资料和库存。页面使用管理员运营壳层，沿用现有药品 HTTP 接口并扩展库存查询和调整能力；医生开药、药费订单和患者缴费继续由各自页面负责。

## 工作台结构

- 摘要卡片：药品品类、启用药品、库存预警和锁定库存数量。
- 筛选栏：药品名称或编号、启用状态、库存预警。
- 库存表格：药品编号、名称、规格、单价、可用库存、库存锁定、总库存、预警阈值、状态和操作。
- 详情抽屉：基础资料、库存拆分、预警状态和消耗记录；消耗记录只显示药费订单状态、数量和时间，不展示患者医疗正文。
- 资料表单：新增或编辑名称、规格、单价、预警阈值和启用状态。
- 库存表单：单独调整总库存，展示当前可用、锁定和调整后可用数量。

## 领域口径

- `可用库存` 是当前可被医生开具并被新药费订单锁定的数量。
- `库存锁定` 是待缴费药费订单暂时占用的数量，对应 `Inventory hold（库存锁定）`。
- `总库存 = 可用库存 + 库存锁定`。支付成功时锁定数量转为消耗，超时释放锁定数量回到可用库存。
- 预警条件为可用库存小于或等于预警阈值。

## 操作边界

- 默认只显示启用药品；停用药品不能被医生开具。
- 有处方历史的药品不可删除，只能停用；无历史药品才显示删除操作。
- 药品资料编辑不修改库存。
- 库存调整不填写原因；后端在事务中重新读取并锁定药品，调整后的总库存不得小于最新库存锁定数量，冲突时返回业务错误并保留表单。
- 金额在界面展示为元，接口继续使用分为单位的 `feeMinor`。

## 接口变化

- 管理员药品列表返回 `availableStock`、`heldStock`、`totalStock` 和 `hasPrescriptionHistory`，保留旧字段兼容已有医生端。
- 新增管理员库存调整接口，接收目标总库存并返回更新后的药品库存；服务层负责锁定、校验和并发冲突。
- 单药品历史接口继续返回药费订单状态、数量和时间，页面不展示患者医疗内容。

## 非目标

页面不处理处方开具、药费支付、药品出库交付、患者资料或医疗正文，也不把库存锁定误称为已取药。
