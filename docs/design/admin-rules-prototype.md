# 管理员全局规则原型

状态：用户确认。关联总需求 #1，沿用 ADR-0015 的业务规则快照目标，不新增 ADR。

## 范围与页面

在现有 `/prototype/admin-home?module=全局规则` 内展示，复用管理员导航和视觉。5 组卡片、12 项规则均沿用 `RulesService.defaults()` 默认值。主页面展示当前值、单位、说明及直观示例；各组通过独立弹窗编辑，不使用详情抽屉。AI 配置、账户安全和单场次号源不在本页。

| 规则组 | 字段与默认值 | 校验 |
| --- | --- | --- |
| 门诊时段 | 上午08:00–12:00；下午14:00–18:00 | HH:mm；上午开始＜上午结束≤下午开始＜下午结束 |
| 签到与候诊 | 开始前30分钟可签到；结束前15分钟截止签到；线上叫号后无应答等待5分钟 | 前两项整数0–1440；等待整数1–240；截止分钟数小于两个门诊中较短的时长 |
| 审批时限 | 最长7天；开诊前24小时硬截止 | 分别为整数1–365天、1–8760小时 |
| 药费支付 | 待缴有效期24小时 | 整数1–720小时 |
| 默认挂号费 | 普通10.00元；专家20.00元 | 0–1000000元，最多两位小数，按整数分保存演示值 |

不额外要求专家费用高于普通费用，也不增加审批小时与天数的比值限制。允许午间无间隔，签到截止值为0时在结束时截止，截止时刻不包含在窗口内。示例随已保存值更新，签到示例可表示前一天；审批以“申请后最长时限与开诊前硬截止取较早值”说明目标规则，避免暗示固定日历日期。

## 修改和确认

一次编辑一组；未变更禁用下一步。先校验本组字段，再将其合入已保存规则进行跨字段校验，错误保留输入并明确提示。缩短门诊导致签到规则冲突时阻止保存，提示先修改“签到与候诊”，不自动调整另一组。

校验通过进入同一弹窗的确认步骤，列出实际变更项的当前值和新值，说明目标生效范围。可以返回修改或确认保存；无必填修改原因。最终确认再次校验，成功后同步卡片、最近修改人/时间和只读修改记录。弹窗关闭按钮、取消、Esc 和遮罩均走统一放弃确认；选择继续编辑保留草稿，明确放弃才清空，并恢复原焦点。

修改记录按新到旧显示本次页面会话的规则组、变更前后值、演示操作者和 Asia/Shanghai 时间，无虚构初始修改记录。时间精确到秒。无版本回滚、恢复默认、删除记录或真实审计联动。

“刷新规则”重新读取本页已确认的演示值，不清空记录或改写最近修改时间；浏览器重新加载或离开模块后重新进入恢复默认演示数据。全页明确标识演示，不读取/写入真实接口或浏览器持久存储。确认说明中的“新业务使用新规则、存量业务保留规则快照”为产品目标，本原型不改变任何真实排班、预约或药费单。

## 后端差距与后续接入

现有 GET/PUT `/api/v1/admin/settings/rules` 保存完整配置，`global_rules` 是单行覆盖，没有对外版本、修改人、更新时间、历史、回滚或并发冲突检查。`/admin/settings` 当前复用 AI 日志页面。本次保留正式入口和后端行为。

ADR-0015 的快照要求尚未完全实现：签到和线上过号实时读取规则，爽约截止仍固定15分钟；普通排班时间固定为08–12/14–18，默认挂号费未被排班消费；审批参数尚未接入现有固定时限逻辑。药费创建时保存时限与到期时间，存量药费单基本符合目标。接真实接口前须修复这些消费链路和快照边界，并补充完整配置的并发更新策略，不能仅换成真实请求后宣称全局规则已生效。

## 验证

通过浏览器公开交互验证默认值、五组入口、逐组保存、金额精度和整数/时段/跨组边界、二次确认前不落值、取消和放弃确认、修改记录和刷新/重载、无真实请求、桌面与手机布局、按钮样式和键盘操作。完整交付须通过 `scripts/verify.ps1` 并创建 Git 提交。
