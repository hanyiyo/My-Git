# 医生工作区真实接入规格

状态：D1–D8 已实现并完成统一验收。正式医生工作区已接通真实身份、队列、接诊、草稿、结构化病历、药费、摘要授权、排班治理、通知和只读资料；完整证据见各任务验收记录，最终汇总见 [D8 验收记录](../acceptance/doctor-workspace-d8.md)。
追踪：总需求 #1；[医生接入父任务 #23](https://github.com/hanyiyo/My-Git/issues/23)。视觉与交互基线：[医生原型](doctor-workspace-prototype.md)。业务依据：[三端修订](three-end-requirements.md)、[最小医疗范围](../adr/0004-minimum-necessary-medical-visibility.md)、[ADR-0015](../adr/0015-three-end-requirements.md)、[会话工作区](../adr/0018-consultation-session-workspace.md)。

## Problem Statement

患者正式首页已接通真实业务，但正式医生首页、队列、诊室与排班页仍是早期基础界面，已确认原型中的工作区结构和草稿、药品、摘要交互未完整接入。医生无法在统一工作区可靠地看清今日任务、继续当前接诊并提交完整病历；原型本地数据也不能承担真实医疗记录。

## Solution

沿用已确认医生原型视觉，在现有 Vue 应用和 Spring Boot、MySQL、Redis 运行栈中，将六个模块逐项接入真实接口。优先复用既有队列、问诊、药品、审批和通知能力，针对已确认但尚无持久化契约的草稿、结构化病历和摘要授权补齐最小接口及迁移。每个子任务从公开接口到页面独立验收。

## User Stories

1. 作为医生，我想登录后看到本人身份、认证和科室，以便确认操作身份。
2. 作为待审核医生，我想看到资格状态及可用入口，以便不会误以为已经可以接诊。
3. 作为医生，我想看到按医院日期统计的今日排班、候诊与完成数，以便安排工作。
4. 作为医生，我想优先继续未结束接诊，否则进入当前或下一场出诊，以便保持患者上下文。
5. 作为医生，我想通过六模块导航和临时标签切换页面，以便不因关闭导航而结束接诊。
6. 作为医生，我想按场次和状态查看、搜索候诊患者，以便找到对应登记。
7. 作为医生，我想先预览资料，再明确叫当前队首，以便避免查看即改变就诊状态。
8. 作为医生，我想在重复操作或另一标签已经叫号时看到冲突，以便不会同时接诊多名患者。
9. 作为医生，我想按真实等待及应答规则标记过号，以便保留患者一次恢复的正确顺序。
10. 作为负责医生，我想在线上诊室读取本次授权图文和附件，以便了解患者情况。
11. 作为线下面诊医生，我想集中填写病历和开药，以便减少无关聊天内容。
12. 作为医生，我想填写五项结构化病历并按挂号自动保存草稿，以便切换或刷新后继续。
13. 作为医生，我想知道草稿是否成功保存及有无版本冲突，以便不会丢失或覆盖记录。
14. 作为医生，我想核对病历和手工填写的药品用法后提交，以便形成完整、可追溯的结果。
15. 作为患者，我想药费超时仍可看到已提交结果，以便付款生命周期不会改变医疗事实。
16. 作为医生，我想只追加更正已提交病历，以便保留作者和历史版本。
17. 作为患者，我想明确授权摘要提供方、用途和本次材料范围，并可拒绝或撤回，以便控制医疗材料使用。
18. 作为医生，我想获得仅自己可见的授权症状摘要，并识别过时或失败状态，以便不把AI作为诊断或处方。
19. 作为医生，我想查询真实排班并从场次发起停诊，以便准确核对受影响范围。
20. 作为替诊医生，我想查看邀请并回应，以便知道同意后仍待管理员复核。
21. 作为科主任，我想只处理本科室非本人申请，以便遵守职责和回避边界。
22. 作为医生，我想通知断线后补齐且已读不改变业务待办，以便不遗漏事项。
23. 作为医生，我想在个人中心查看真实资料并安全退出，以便不会误操作尚未接通的编辑能力。
24. 作为医生，我想在375px浏览器中用键盘操作导航和弹窗，以便完成核心工作。
25. 作为医生，我想数据失败时看到重试和未保存说明，以便区分业务事实与失败草稿。

## Implementation Decisions

- 身份与资源归属由服务端认证主体判定。首页不含医疗正文；预览只返回负责医生在当前预约可见的最小范围。无权、过期、服务失败和空数据分别呈现。
- 首页只导航，不叫号或审批。统计待接诊只计已缴费、已签到且WAITING的患者；接诊中和已完成独立计数，历史结束或作废不混入候诊。首页及排班使用服务端医院时区日期和快照时间，不硬编码08:00/14:00或24小时截止。
- 沿用正式深链接，六模块为首页、接诊工作台、我的排班、申请处理、站内通知、个人中心。新增入口按真实角色校验。医生临时标签本期限当前浏览器页面导航状态，刷新按URL回到当前业务；跨登录标签恢复不在本期。[患者标签ADR](../adr/0017-temporary-workspace-tabs.md)的账户Redis缓存约定不自动扩展到医生医疗草稿。
- 候诊列表已有按医生、日期、排班查询，但单接诊及队首约束必须补服务端并发检验；搜索不得改变真实队列顺序。已开始接诊不因关闭标签或排班结束而自动完成。
- 草稿是新的受控持久化记录，按负责医生及预约隔离、版本化保存于MySQL，失败保留输入。Redis仅可承载验证码、登录限流及可重建缓存，不能承担病历、草稿或预约一致性。
- 病历保存主诉、现病史、既往史/过敏史、诊断、处理建议；提交时主诉、诊断、处理建议必填。开药记录增加医生手填用法用量与现有数量/价格快照协作，旧文本结果继续可读。只在需要的clinical/pharmacy模块增加兼容迁移，不重写业务状态机。
- 医疗结果和可选开药沿用现有事务协调：库存不足整体拒绝、保留草稿；成功后病历只读，追加更正保留版本和审计。支付和超时只影响药费订单及库存，不回滚医疗结果。
- 既有图文摘要入口只检查是否有共享材料，缺少提供方/用途/消息版本授权及持久摘要版本，因此不是已完成的授权能力。补齐患者授权、撤回、负责医生检查和精确输入范围；新增未授权内容不外扩。摘要仅医生可见，不自动填诊断或药品、不读取患者独立AI会话。
- 本期摘要提供方明确使用LOCAL_MOCK并标注。授权范围内消息变化受控更新、支持手动重生成，旧结果失效及过时状态清楚可见，失败不阻断诊疗。真实外部AI及图片识别另立后续规格。
- 排班读接口缺少临时占号、确认占用细分及申请影响计数，科主任资格也不能靠“收件箱非空”推断；仅补必要的受保护计数/能力读契约。停诊、替诊和管理员最终复核复用现有应用服务及规则快照。
- 本期通知只交付当前已有的本人列表、未读、单条已读和业务深链接；阅读不代表处理申请。医院新闻、通知删除与批量操作、资料编辑和改密不以假成功占位。

## Testing Decisions

- 业务验收使用既有公开REST、真实MySQL/Redis、fake clock和Playwright，不把Vue内部状态或静态文案存在当成实现完成。新契约沿用相同HTTP边界。
- 复用现有身份、候诊/接诊、问诊、药费、替诊、通知HTTP及浏览器测试，保留患者首页201项回归基线。扩展正向、拒绝及关键边界，服务端约束不能仅由浏览器mock证明。
- 每个子任务先建立acceptance record，记录所用公开接口、测试及剩余限制。验收矩阵R01–R12必须全部映射任务；任务依赖必须无环、引用可解析。
- D8覆盖患者挂号/签到→医生首页/队列→线上图文或线下面诊→核对提交→患者只读结果/独立药费，并验证单场停诊替诊、通知断线补齐及权限。
- 每次完成变更依仓库门禁执行未筛选的完整验证，成功后双轴审查、记录证据并创建Git commit；D8 已完成本地统一验收，父任务和子任务的 GitHub 状态按发布策略另行更新。

## Out of Scope

真实支付、外部AI提供方、OCR或图片识别，新的患者独立AI会话，管理员首页真实接入与新闻发布后台，医生资料编辑/手机号验证/改密，通知删除/批量已读，新增调班/请假状态机、排班创建发布能力，以及跨登录医生临时标签恢复。既有患者资料、医疗附件、挂号和通知行为继续回归。

这些是本期范围边界，原型相关功能仍作为总需求的后续工作保留，不能凭本规格宣称总需求 #1 完成。

## Further Notes

开发原型继续独立保留，正式构建不携带原型路由、演示身份或业务存储键。LOCAL_MOCK是显式的提供方模式，和隔离开发原型是不同要求。D1 的验收记录见 [doctor-workspace-d1.md](../acceptance/doctor-workspace-d1.md)，后续实现仍逐项验证。
