# 管理员药费订单工作台原型

状态：已确认并实现。入口为 `/prototype/admin-home?module=药费订单`，使用虚构演示数据，不连接真实管理员药费订单接口。

## 页面定位

药费订单工作台只管理医生开药生成的 `Medicine payment order（药费订单）`。挂号支付订单不混入列表；关联挂号只作为运营上下文展示和跳转目标。管理员拥有只读运营权限，可以查看、筛选、刷新、复制订单号和关联挂号号，不能代付、改价、强制改变状态或人工关闭订单。

页面默认按医院业务日（Asia/Shanghai）展示今天创建的全部状态订单。日期范围最多覆盖近一年，订单状态以数据源返回为准；页面只在待缴费订单距截止不足 30 分钟时增加“即将到期”提示，不替后台任务推进状态。

## 页面结构

- 摘要卡片：今日订单总数、待缴费数量、已支付数量/金额、已失效数量；待缴费卡片额外显示临近截止数量。
- 筛选栏：开始日期、结束日期、订单状态、医生、科室、患者/订单号/药品关键词，以及重置筛选。
- 订单表格：订单号和关联挂号号、患者姓名和患者编号、医生/科室、前两项药品摘要、订单金额、药费状态、创建/截止或支付时间、详情入口；按创建时间倒序。
- 详情抽屉：订单状态、金额快照、创建/截止/支付时间、完整药品明细、关联挂号摘要、订单时间线和复制/跳转操作。

## 状态与隐私边界

- 药费状态只有待缴费、已支付和已失效三种展示口径。
- 关联挂号同时展示挂号号、医生、科室、日期/门诊时段、线上/线下和挂号状态；两个状态分别读取，挂号取消或完成不自动改写药费订单状态。
- 患者展示姓名和患者编号，不显示手机号。
- 药品明细展示名称、规格、单价、数量和小计；不展示病历、症状、处方用法用量或其他医疗正文。
- 药费订单的已支付表示库存已消耗，已失效表示超时后库存已释放；这些说明不改变订单事实。

## 首页联动与限制

- 管理员首页侧栏“药费订单”进入本模块，仍保留运营总览、预约与订单、药品与库存等导航。
- 详情抽屉跳转 `/prototype/admin-orders?tab=appointments&date=ALL&keyword=<关联挂号号>`，只带关联编号，不开放医疗内容。
- 原型使用固定演示数据；后续真实接口需要按同一字段和状态边界提供管理员查询能力。
