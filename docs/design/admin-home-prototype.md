# 管理员首页原型

状态：已确认并实现 A 版原型。入口为 `/prototype/admin-home?variant=A`，使用虚构演示数据，不连接真实业务接口。

## 设计目标

管理员首页采用“运营驾驶舱”定位，第一屏服务值班处理而不是只展示报表。页面按“指标 + 待办 + 风险”组织信息，管理员可以从待处理事项直接打开对应模块；复杂流程进入独立页面，轻量查看使用右侧抽屉。

桌面端采用可收缩左侧导航、顶部医院与管理员身份、浅蓝和青绿色医疗视觉；主要适配 1280–1440px 桌面宽度，兼容 1024px 平板可读性。单医院场景不提供医院切换器。

## 管理模块覆盖核对

需求中的业务主线已经覆盖患者、医生、科室、排班、号源、药品、全局规则、停诊替诊终审、新闻通知和运营统计。现有实现已有目录/排班、药品、治理审批、医疗访问、AI 调用元数据和基础账号页面，但此前没有完整管理员首页，也没有把运营异常和权限边界组织成统一工作台。

首页当前保留以下补充入口：

- **预约与订单、退款/异常**：覆盖未支付占号、付款、退款失败等运营例外。
- **审计日志**：让停诊、替诊、退款、内容限制和医疗访问操作可追溯。
- 审计日志原型已在现有模块入口实现，只读查询管理员运营操作；范围与后续接口限制见[审计日志设计](admin-audit-prototype.md)。
- **医疗访问审核（暂隐藏）**：作为可选扩展，按用户后续要求从所有管理员导航、正式首页和首页待办中隐藏，保留代码、旧深链接、独立授权、理由和审计边界。

## 页面结构

侧栏分为运营、资源、药品、治理、系统五组。顶部显示医院名称、管理员身份、数据更新时间、通知入口和刷新动作。首页内容如下：

1. 问候区：当前日期、系统运行状态和当天运营重点。
2. 今日运营摘要：今日挂号总量、线上/线下分布和紧急事项入口。
3. 时间范围：今日或近 7 日；卡片显示今日值，趋势图显示近 7 日。
4. 指标卡片：今日挂号、今日完成接诊、待处理事项、库存预警。
5. 趋势图：近 7 日挂号量，配合线上/线下说明。
6. 今日出诊安排：科室、医生数、服务方式、号源使用和接近满号提示。
7. 待处理事项：按“需要马上处理 / 今天处理 / 提醒”分级，包含终审、退款失败、开诊、未支付占号、库存预警和新闻草稿。
8. 科室挂号分布：展示今日有效登记的相对分布。

## 交互与边界

- 首页待办按紧急度排序，红色表示需要马上人工介入，橙色表示今天处理，蓝色表示普通提醒。
- 库存预警、审批摘要和退款失败可以在抽屉内快速查看；新建排班、订单处理进入对应管理页面。
- “刷新运营数据”只更新原型中的更新时间提示；演示数据保持稳定，明确标注不连接真实业务接口。
- 原型只实现 A 版均衡驾驶舱，不实现 B 版待办优先或 C 版数据分析方案。
- `variant` 查询参数保留为入口兼容标识，当前页面只呈现 A 版布局。

## 验收边界

- `/prototype/admin-home?variant=A` 可见管理员侧栏、运营指标、待办、风险提示和今日排班。
- 侧栏可以收缩；移动宽度可以打开和关闭导航，不产生横向溢出。
- 今日/近 7 日切换、刷新、待办抽屉、进入模块按钮均可操作。
- 侧栏保留默认未开启的医疗内容权限说明；不提供医疗访问审核入口或待办，首页不展示医疗正文或附件。
- 页面不发起 `/api/` 请求，所有数据为虚构演示数据。
