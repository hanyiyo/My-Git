# 管理员审批与替诊工作台原型

状态：已确认并实现。入口为 `/prototype/admin-home?module=审批与替诊`，使用虚构演示数据，不连接真实治理接口。

## 页面定位

工作台只处理停诊/替诊链路的管理员最终复核：直接停诊、普通替诊和紧急停诊/替诊。医生资质审核、医疗访问审核等治理流程不混入本页。默认展示“待管理员复核”，可切换查看全部状态。

## 页面结构

- 摘要卡片：待管理员复核、紧急处理、替诊待确认、近 7 日已处理。
- 筛选栏：处理状态（待处理 / 已处理 / 全部工单）、提交日期范围、关键词和重置筛选。默认选择待处理，待处理包含科主任审核、替诊医生确认和管理员复核；已处理包含已驳回、已停诊、已替诊和紧急停诊。
- 工单表格：工单编号、申请类型、原医生/科室、出诊日期与时段、替诊医生、当前状态、提交时间、截止提醒和详情入口；按提交时间倒序。
- 详情抽屉：原排班、申请理由、资质/科室/时间冲突校验、患者影响、迁移或退款预览、只读原因、排班和预约跳转。
- 审批弹窗：通过替诊、直接停诊、驳回和紧急处理均二次确认；驳回与紧急处理必须填写理由，紧急替诊要求逐患者选择接受替诊或拒绝并退款。

## 状态和权限

页面展示 `HEAD_REVIEW`（待科主任审核）、`SUBSTITUTE_REVIEW`（待替诊医生确认）、`ADMIN_REVIEW`（待管理员复核）、`HEAD_REJECTED`（已驳回）、`APPROVED_STOP`（已停诊）、`APPROVED_SUBSTITUTE`（已替诊）和 `EMERGENCY_STOP`（紧急停诊）。只有 `ADMIN_REVIEW` 工单可执行管理员动作；其他状态显示当前责任人或只读原因。距出诊不足两小时仅增加“紧急处理”提示，不自动改变工单状态。

普通替诊通过后预览自动迁移有效挂号；直接停诊预览取消受影响挂号并对已付款挂号进入退款流程；紧急替诊逐患者记录接受或拒绝。管理员不能在此替换替诊医生，只能驳回申请让申请链路重新选择。

详情和患者影响只展示姓名、患者编号、挂号状态、排班与退款/迁移结果，不展示病历、症状、处方、用法用量或其他医疗正文。跳转只携带排班日期、工单编号或挂号工作台关键词。

## 实现限制

当前为本地稳定演示数据，审批提交只更新页面内状态并给出反馈；真实接口接入时需保持同一状态边界、校验顺序和患者隐私范围。
