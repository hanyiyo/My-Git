# 当前 MVP 范围

Q31–Q48 已由用户确认，Q44 按用户修订采用“出诊开始前 30 分钟至结束前 15 分钟”的签到窗口。本文件是当前阶段范围入口；早期访谈记录保留在 [MVP 决策](mvp-decisions.md)，完整功能目标见 [产品目标](product-vision.md)，运行行为见 [接诊规则](reception-rules.md)。整体架构和全部业务规则仍待访谈收敛确认，本阶段不实现业务代码。

## 首版覆盖

| 范围 | 已确认能力 |
| --- | --- |
| 医院与角色 | 单医院；患者、医生、管理员三端；科主任为医生附加的科室管理权限 |
| 线上预约问诊 | 选医生和时段、临时占号、模拟支付、预约凭证、签到候诊、医生叫号后图文接诊 |
| 线下预约 | 选医生和时段、临时占号、模拟支付、预约凭证、签到候诊、医生叫号后登记面诊结果 |
| 现场挂号 | 选择当天可用服务，完成登记及模拟支付，进入线下签到候诊流程 |
| AI | 文本导诊；独立普通业务咨询入口；预问诊摘要经患者确认后带入问诊 |
| 医生及管理 | 医生资质人工审核；科室、排班与号源管理；停诊替诊审批；预约管理、受控问诊审核、AI 调用日志 |
| 通知与记录 | 站内通知；问诊记录与共享档案；按权限访问的图片/PDF等白名单附件 |

首版继续采用 Spring Boot 模块化单体、REST API、MySQL 和一个 Vue 应用。实时消息传输方式、存储和任务基础设施尚未选定。

首版仅成年本人挂号，使用虚构身份与医疗数据；验证码、找回密码、实名认证为明确标识的演示适配器，不发送短信邮件。Windows 本机开发，提供单台 Linux 部署方案；优先桌面，患者页面兼容手机浏览器，无小程序或原生 App。

## 支付与号源

Q36 确认的登记流程为：

1. 提交登记并临时占号，默认保留 10 分钟。
2. 模拟支付成功且临时占号仍有效时，确认预约并继续占用该号源。
3. 超时或主动取消解除临时占号；是否可再次预约还要看排班是否正常开放。
4. 占号失效后才收到成功付款结果时，全额模拟退款，不恢复原预约或挤占其他患者号源。

模拟支付是首版支付适配器，不能发起真实收款。付款、退款、临时占号各自可追踪；付款成功不等于已签到或完成就诊。患者在预约开始前取消、医院直接停诊或拒绝替诊，全额模拟退款；开始后、爽约及接诊后的退款由管理员人工处理并记录理由。退款失败可重试，不恢复已取消预约或开放停诊号源。

本条替代原先“不建支付订单、提交即确认”的阶段范围，见 [ADR-0011](../adr/0011-paid-booking-holds-mvp.md)。

## 停诊与替诊

- 正常停诊至少提前 24 小时申请；科主任决定直接停诊或寻找替诊；替诊医生如适用先确认；管理员复核并调整排班。
- 直接停诊：解除患者对原号源的占用，同时停用整次出诊号源。通知患者重新选择其他有效排班，不能重新预约原停诊名额。
- 正常排班上的患者主动取消：在允许取消时解除占用后，号源可再次预约。
- 替诊：管理员复核后通知原预约患者；患者选择接受或取消，等待选择期间保留其名额。替诊医生仅能查看已接受替诊患者授权共享的医疗材料。
- 替诊医生必须同科室、资质已通过、排班无冲突；拒绝后回科主任重新选人或直接停诊，管理员最终复核时重新校验。
- 科主任自身申请交管理员审核；紧急停诊由管理员执行并填写理由。
- 正常患者替诊确认截止为通知后 2 小时与出诊前 2 小时的较早者；逾期未接受则取消退款并提醒。复核时不足提前 2 小时转人工紧急处理，不默认接受。
- 有效停诊申请提交即暂停新增挂号；未付款登记禁止继续支付、解除占号，已付款预约保留至最终方案。驳回或撤回恢复正常剩余号源，临近出诊未审完提醒管理员，不自动停诊。
- 接受替诊后撤销原医生对本次未接诊材料的访问；历史医疗记录保留作者版本，更正追加并审计，不覆盖或重开诊室。撤回授权限制后续访问，不删除已形成记录。

## 排班、候诊与接诊

- 每次出诊指定线上或线下，同一医生出诊时间不重叠；现场挂号使用当天线下剩余号源。
- 按医生、线上/线下、日期、时间段配置排班和每段多个号源；默认开放未来 7 天，时段开始停止新增挂号，现场只选当天尚未开始时段。
- 按预约时间段优先、同段签到顺序候诊；现场挂号不默认插队。过号可重新报到排当前时段队尾，人工调整须写原因。
- 签到自医生出诊开始前 30 分钟开放，结束前 15 分钟截止；患者在订单页签到或管理员代签，成功进入队列。截止未签到记爽约，已签到候诊不因医生延迟记爽约。
- 诊前可以填症状与上传材料，正式图文交流在医生叫号接诊后开放。
- 医生提交结果并结束接诊后预约完成、诊室只读，复诊新建预约；排班时间结束不自动切断正在进行的接诊。
- 状态边界见 [ADR-0012](../adr/0012-separate-booking-payment-and-encounter.md)，整次出诊与患者细分预约时段、线下到场核验仍需澄清。

## AI 入口与授权

- 医院位置、挂号流程、科室一般职责属于普通业务咨询或一般科室知识；不自动带入个人健康档案。
- 患者描述自己的症状或提交报告，进入预问诊确认流程；授权前不能将相应个人医疗内容发给外部 AI。
- 患者拒绝授权后仍能自行预约及使用医生服务。外部提供方还必须由部署配置显式启用。
- 普通咨询不作为个人医疗数据免授权外发的路径；入口识别和内容筛选机制需在架构阶段细化。
- 调用日志与医疗正文分离；医生最终判断原则不变。

## 后续迭代

- 语音输入、图片/OCR 的 AI 分析；首版可保存附件不代表首版自动分析附件。
- 真实支付渠道、评价、复杂统计、知识库及自动化运维监控。
- 医生开单、模拟缴费、检查、取药、病历归档的院内流程扩展；不在首版实现，不接真实收费、检验、影像和药房系统。
- 实时音视频不进入首版；图文交互时序见接诊规则，消息传输方式仍待架构阶段选定。
