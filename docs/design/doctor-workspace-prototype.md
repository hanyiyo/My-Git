# 医生端总体布局与首页原型

状态：Q1–Q8 和整体理解均已确认，用户已授权开始制作；第一阶段首页与总体框架已实现，等待完整验证。需求文本与参考图作为设计参考，延续患者端原型风格，优先验证接诊与停诊流程。现行业务边界见[三端修订规格](three-end-requirements.md)、[ADR-0015](../adr/0015-three-end-requirements.md)和[会话工作区决策](../adr/0018-consultation-session-workspace.md)。

## Q1：首页承担今日任务总览

首页展示今日出诊、候诊概况、继续接诊与待办提醒，点击入口进入专门的接诊工作台。聊天、病历编辑和开药集中在接诊工作台。

总体模块为：首页、接诊工作台、我的排班、申请处理、站内通知、个人中心。申请处理包含医生自己的停诊申请和替诊邀请，科主任额外拥有本科室审批入口；科主任仍属于医生端。Q6 将讨论初期的“停诊与替诊”菜单与处理页面统一命名为“申请处理”。

视觉沿用患者端的浅色背景、蓝绿配色、圆角卡片、可收缩侧栏和顶部临时标签。首页以欢迎与出诊信息、待接诊/就诊中/今日已完成/待处理申请概况、今日排班与候诊预览、右侧待办、下方公告构成。公告轮播降低占比，优先展示接诊任务。

## Q2：线上线下共用接诊工作台

线上问诊和线下面诊共用接诊工作台，按出诊安排切换。线上展示医患聊天与医生症状摘要，线下突出病历录入，两者共用病历和开药区域。AI 症状摘要、病历、处方均属于当前患者的接诊上下文；历史记录从当前患者进入，仅展示有权访问的内容。

线下面诊不创建医生聊天会话；患者 AI 助手会话与医生问诊分离，医生症状摘要仅医生可见。医疗结果提交即保存，药费订单保持独立生命周期，不能因药费未支付而阻止病历保存。

## Q3：通过共享演示数据验证医患联动

后续原型支持实际切换医患两端，围绕同一笔演示挂号查看状态变化。医生叫号后患者显示就诊中；医生完成后患者可以查看病历；停诊或替诊结果同步展示到患者端。演示采用共享演示数据，真实接口接入属于后续阶段。

按阶段先确定总体框架并制作首页，随后补齐接诊与停诊两条演示流程。Q3 是后续原型的验收目标，不表示当前已有联动实现。共享范围、刷新恢复和演示审批方式已在 Q7–Q8 确认。

停诊最终生效与退款处理状态分别展示；替诊经最终复核后自动迁移有效预约并通知患者，患者无需确认接受。首页与导航不改变这些既有业务规则。

## Q4：首页突出当前或下一场出诊

首页默认突出当前正在出诊的一场并展示候诊预览；没有当前出诊时展示下一场，同时保留今日全部排班供查看。

## Q5：手动叫号并优先继续当前接诊

医生手动叫下一位，完成接诊后不自动叫号。若已有未结束的接诊，首页主按钮显示“继续接诊”，先处理当前患者。

## Q6：申请操作集中在申请处理页面

首页的停诊、替诊待办只显示摘要与入口。具体申请、替诊确认和科主任审批统一进入“申请处理”页面完成，首页不直接执行确认或审批。

## Q7：同一浏览器共享并保留演示进度

医患联动演示限定在同一浏览器，支持不同标签页同步，刷新后保留演示进度，并提供“重置演示”恢复初始数据。共享内容为虚构演示业务进度；这项约定适用于后续医患联动原型，不改变真实业务存储规则，也不承诺原型接通真实后端。

## Q8：独立演示控制区切换审批身份

产品页面之外设置独立演示控制区，用来切换科主任、替诊医生等演示身份，并推进管理员复核结果。医生页面只显示当前身份有权处理的事项；演示控制区不成为正式产品的身份切换或越权审批入口。

## 分阶段交付与整体确认

第一阶段按用户最初要求制作医生端首页与总体布局，展示六个模块的导航、首页出诊与候诊概况、继续接诊入口和申请待办入口。接诊工作台及申请处理的完整内部页面随后分阶段细化；首页阶段不将未完成的联动或审批标为可用。

后续阶段补齐同一笔演示挂号的医患联动、线上线下接诊以及停诊/替诊审批演示。每阶段分别验证和提交，保留 Q1–Q8 约定。用户已确认整体理解并授权第一阶段页面实现。

## 第一阶段实现说明

开发原型入口 `/prototype/doctor-home`，一条命令 `npm run prototype:doctor` 启动；医生端保持一个已确认的首页布局。使用患者端现有图标和公告素材，延续配色、可收缩侧栏、顶部品牌和可关闭临时标签。

首页支持姓名/排队号搜索、患者资料预览、公告阅读，以及进入六个模块的上下文预览。待接诊仅统计已缴费且已签到患者；出诊卡与今日全部排班并列呈现。存在未结束接诊时主入口显示“继续接诊”并保留患者上下文，首页不执行叫号。申请待办点击后统一进入申请处理，科主任增加本科室审批摘要。

独立演示设置提供“上午出诊中 / 有未结束接诊 / 等待下午出诊 / 今日出诊结束”四种场景及普通医生/科主任身份。仅将虚构的身份和场景保存在浏览器本地，支持同浏览器标签页同步和刷新恢复；损坏设置可恢复默认值，存储不可用时提示。重置有二次确认，不改动患者原型数据。

第一阶段的接诊工作台、排班、申请处理、通知和个人中心是只读结构预览，明确说明后续制作范围。患者端按钮只在新标签页打开已有患者原型，不表示医患业务状态已联动。完整审批推进与管理员复核结果控制仍待后续阶段实现。所有原型路由和页面资源仅在开发环境加载。

验收记录见[医生端首页验收](../acceptance/issue-1-doctor-home-prototype.md)。
