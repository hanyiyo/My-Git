# 管理员资源模块原型规划

状态：已确认并实现 A 版原型。页面统一采用管理员端 A 版视觉和交互模式，使用虚构演示数据，不连接真实资源接口。

## 页面结构

资源模块由患者、医生、科室、排班 / 号源四类工作台组成。账户治理已融合到患者和医生详情抽屉，不再单独提供账户管理工作台；排班 / 号源保持独立，不并入医生或科室详情。

三页共用左侧资源导航、摘要卡片、筛选栏、数据表格、右侧详情抽屉和操作反馈。页面使用虚构演示数据；每个页面完成后单独提供访问路径和专属浏览器验收。

## 患者资源工作台

页面定位是患者资料目录，不是病历管理页。

- 列表字段：姓名、登录账号、脱敏手机号、注册来源、账户状态、注册时间。
- 筛选：关键词、账户状态、注册时间；日期使用日历下拉框。
- 新增：姓名、手机号、登录账号，创建后账户默认启用，并进入详情抽屉显示成功提示。
- 详情：只展示患者资料和账户状态；预约信息通过按钮跳转预约运营工作台，页面不展示病历、问诊、医疗附件或预约正文。
- 操作：启用 / 停用账户、锁定 / 解除登录锁定、重置登录状态；高风险操作二次确认。停用只影响登录，不取消预约、不删除历史记录。

## 医生治理工作台

页面定位是医生资源治理和资质工作台，不替代医生端工作台或排班页面。

- 列表字段：姓名、账号、职称、所属科室、资质状态、科主任标记、排班摘要、账户状态。
- 筛选：关键词、资质状态、科室、账户状态、是否科主任。
- 新增：姓名、登录账号、职称、所属科室，资质默认“待审核”；创建后进入详情抽屉。
- 详情：账户关联、医生资料、资质时间线、所属科室、科主任标记和排班摘要。
- 操作：资质状态变更、科室归属调整、科主任标记；每个科室最多一名科主任，任命新的医生会替换原负责人；资质变更必须填写审核备注并记录操作时间。排班通过入口跳转排班页面。
- 账户启用 / 停用、锁定 / 解除登录锁定、重置登录状态可直接在本页执行；这些操作不改变资质、科室归属或既有排班。

## 科室管理工作台

页面定位是科室主数据和关联关系管理，不承载全部医生资料或排班编辑。

- 列表字段：科室名称、启用状态、科主任、医生数量、未来排班数量、服务说明摘要。
- 筛选：关键词、启用状态、是否有负责人。
- 新增：科室名称、服务说明、启用状态；科主任后续单独任命。
- 详情：科室说明、服务方式、负责人、医生列表和排班摘要。
- 操作：编辑主数据、启用 / 停用科室、任命 / 更换科主任；每个科室最多一名负责人，负责人只能从本部门已认证医生中选择。
- 停用前提示影响并保留历史记录；停用后禁止新排班和新预约，不自动取消或删除已有历史业务。
- 科室页只维护科室主数据和负责人，不承载医生账户治理。

## 交互和状态边界

- 患者、医生、科室三页都提供新增按钮；新增成功后打开对应详情抽屉并显示成功反馈。
- 账户启用 / 停用、资质审核、科室停用、科主任任命等操作需要清晰反馈；停用、资质驳回和科室停用属于高风险操作，需二次确认或填写理由。
- 角色变更、医疗访问审核、预约履约和排班明细分别由治理、医疗访问审核、预约运营和排班页面负责；患者和医生详情负责各自账户治理。
- 所有日期筛选统一使用日历下拉框；窄屏下表格可滚动，侧栏可打开和关闭。

## 实现顺序和入口

1. 患者资源工作台：提供患者资料和完整账户治理。
2. 医生治理工作台：加入资质状态、科室关联和审核备注。
3. 科室管理工作台：加入科主任任命和停用影响提示。

访问入口：`/prototype/admin-patients`、`/prototype/admin-doctors`、`/prototype/admin-departments`。三个页面均可从管理员首页“资源”导航进入。
